AI-DCC → UE5
美术资产流水线

资产从 Blender 到 UE5 的路上，问题大多不是导不进去，而是导进去两周后才发现错了。这条流水线让每个问题在导出前、导入前就被拦下，并且每一步都留下证据。{{c.ch}}

AI 使用Codex / Claude 辅助开发；DeepSeek API 解释校验报告（人工确认后执行）

01 · 解决什么问题

问题发现得越晚，
返工越贵。

  • 01规范靠人记命名前缀、单位缩放、材质槽、法线和 UV，每次导出都靠美术自己检查，漏一项就带着错进工程。
  • 02错了很久才发现资产进内容库两周后才在场景里暴露问题，这时已经被引用，改起来牵一发动全身。
  • 03两端各说各话Blender 导出时检查过什么、UE 导入时又该检查什么，没有共同的记录，出了问题追不到是哪一步。
  • 04AI 直接改资产不可控让 AI 自己写脚本修模型，改了什么、为什么改都说不清，也没法回退。
02 · 能做到什么

两端共用一套规则，
每一步都留下证据。

  • 01导出前在 Blender 里判定命名前缀、未应用缩放、未命名材质槽、UV 与法线当场报出，定位到具体对象；支持整体导出或按资产分组导出，单个资产失败不阻断其他资产。
  • 02导出时同步落盘证据FBX / OBJ / glTF-GLB / USD 与 metadata、validation report（JSON）、CSV 同名并列，UE 侧按同一命名去找。
  • 03UE 原生规则库自研 UE 5.8 C++ 编辑器插件：规则 / 规则组 / 规则集三棵树，12 种比较算子，组合规则沿“模型 → 材质 → 贴图”依赖链展开；保存时校验 id、目录和子规则，坏文件逐条报错不中断。
  • 04资源审查能力目录覆盖贴图（压缩、sRGB、Mip、源图尺寸…）、静态网格、骨骼网格（面数、UV、最大影响骨数、Morph…），任意类的可编辑属性走反射；按资产注册表匹配、只在需要时加载，大目录可取消。
  • 05结果可定位、可豁免结果表可筛选，双击定位到内容浏览器；豁免必须填写原因才能保存；报告导出 JSON / TXT，不覆盖旧报告。
  • 06管线阶段有人把关用 MCP 把管线阶段封装成工具：只读计划、按轮数授权写入、检查出错就阻止写入、改动后旧证据自动失效，自动检查通过后仍要人工签字。

可行 01 · 人工验收

规则库与资源审查已过

在目标 UE 5.8 工程里逐项手动操作：规则增删改、能力目录、审查结果与资产 Details 的实际值核对、豁免、导出报告。

可行 02 · 一份契约

C++ 与 Python 结果一致

C++ 侧镜像 Python 的规则校验，错误文本相同、写出的规则逐字节一致；C++ 导出的报告过 Python 契约校验。

可行 03 · 不放行

读不到就报错

读取失败、类型不符、阈值非法、未知能力都会报问题，不会默默当作通过。

可行 04 · 可回溯

报告带运行记录

报告记录检查范围、规则摘要、匹配数和是否取消，可以进版本库比对差异。

05 · 有什么问题

还没证明的，
就不往外说。

  • 待验收
    导入检查（拖入 FBX 时自动检查、按规则阻止）和管线 Tab 已编译、自动化测试通过，但还没在编辑器里人工验收。
  • 插件加载
    插件从工程 Plugins 目录加载的证据还要在目标工程里补一次；早期验收是把仓库加进 Python 路径做的，不能算数。
  • 范围
    受控导入目前只覆盖静态网格；材质、骨骼、动画、视觉效果和运行时性能还没有宿主验收。
  • 没有提效数字
    人工流程的基线还没测，所以只证明“拦得住”，不写节省了多少时间。
  • AI 与安全
    报告解释调用外部 API，离线时只能看原始报告；Agent 的网络出口还没接入安全层，写入、删除、命令目前一律拒绝。
06 · 怎么做的

四层，各管一段。

  • 01契约层metadata、报告与规则由共享契约和 JSON Schema 约束，Python 与 C++ 两端共用同一套样例测试。
  • 02Blender 插件预检、导出、文档落盘、只读修复计划与人工触发的 AI 解释。
  • 03UE 插件C++ 编辑器模块：规则库、能力注册表、审查引擎、导入检查与结果 UI；Python 桥保留发现、导入和复检。
  • 04MCP 管线把阶段、检查和授权封装成工具，给 AI 代理调用；写入要授权，关卡要人工签字。
